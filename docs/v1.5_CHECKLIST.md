# v1.5 重构清单：从“知识图谱”到“因果推理工作台”

> 审阅版。本清单把用户 2026-06-20 反馈的 6 大问题拆分为可执行、可验收的子任务。
> 目标：v1.5 不再只是一个 3D 知识图谱，而是一个支持“关联 → 干预 → 反事实”三层推理的因果分析与任务执行工作台。

---

## 0. 总体架构调整

### 0.1 界面布局重新定义

| 区域 | 职责 |
|---|---|
| 顶部标题栏 | 项目信息、版本、全局搜索入口 |
| 左侧边栏 | **导航与视图**：节点树/层级视图、全局视图切换、图例、帮助 |
| 中央画布 | 3D 图谱 / 3D 执行甘特图 / 因果图（按当前模式切换） |
| 右上浮动工具矩阵 | AI、学术、视觉监督、证据审查、**认知训练**（5 个） |
| 底部控制台 | **输入**、**时序/执行工作台**、**逻辑推理**（原 Agent） |
| 浮动便签 | 节点详情（点击节点后在节点右侧附近弹出） |

### 0.2 底部控制台 Tab 重组

```text
[输入]  [时序/执行]  [逻辑推理]
```

- **输入**：手动添加节点、关系连接、AI 辅助打标/摘要、逻辑树文本输入。
- **时序/执行**：3D 执行甘特图、任务规划、学习工具与任务流、项目教练/研究员 Agent 调度。
- **逻辑推理**：推理线程管理（关联/干预/反事实三层）、证据链与因果分析。

## 1. 箭头与选中高亮

### 1.1 全局箭头样式

- 箭头长度从 `6` 降到 `3`。
- 箭头颜色使用与 link 一致的低透明度颜色，例如 `rgba(148,163,184,0.35)`。
- 默认 link opacity 再降低一档，在 cluster/simplified 模式下进一步降低。

### 1.2 选中节点时关系高亮

- 当 `selectedId` 存在时，所有与该节点直接相连的 link：
  - link color 变为高亮（例如 `#facc15` 或节点同色高亮）。
  - link width 增加。
  - 箭头颜色变为高亮且 opacity 提高。
  - 非相关 link 变暗（opacity 0.1）。
- 相关节点也可以轻微高亮（可选）。

- `components/Graph3D.tsx`
- `lib/graph-utils.ts`（可能需要新的 link 高亮辅助函数）

## 3. 时序编辑器重构为“多维空间执行工作台 / 任务-时间-指标分布工作台”

### 3.1 命名与定位

- 底部 Tab 名称改为 **“时序/执行”**。
- 它不再只是“事件文字列表”，而是把任务投影到**多维空间**的可视化工作台：
  - 核心维度：时间轴（x）+ 重要性（y）
  - 可扩展维度：用户可添加任意数量的自定义指标轴（如紧急度、难度、风险、认知负荷等）
  - 当前激活的两个非时间维度构成可视化平面，用户可自由切换组合

### 3.2 核心数据结构扩展

在 `lib/types.ts` 中扩展 `TimelineEvent` 为更丰富的 `ExecutionTask`：

```ts
export interface ExecutionTask {
  id: string;
  title: string;
  description?: string;
  // 时间轴（固定维度）
  startDate: string; // ISO datetime
  endDate?: string;
  // 核心指标（固定维度）
  importance: number; // 0-1
  // 可扩展自定义指标（用户可添加任意数量）
  metrics: Record<string, number>; // 如 { urgency: 0.8, difficulty: 0.5, risk: 0.3 }
  // 关联
  nodeId?: string;    // 关联知识节点
  parentTaskId?: string;
  dependsOn?: string[];
  // 执行属性
  learningTools?: string[];
  deliverables?: string[];
  status: 'todo' | 'doing' | 'done' | 'blocked';
  createdAt: number;
  updatedAt: number;
}

export interface MetricDefinition {
  id: string;
  name: string;
  unit?: string;
  min: number;
  max: number;
  colorScale: string; // 如 'viridis', 'coolwarm'
}
```

### 3.3 可视化形态

- **多维甘特条**：每个任务是一个沿时间轴（x）延伸的长方体/柱状体，其高度由当前选中的指标轴决定。
- **维度切换面板**：用户可自由选择 y 轴和颜色轴对应的指标（重要性、紧急度、难度、风险等）。
- **指标轴管理**：支持添加/删除/编辑自定义指标定义（名称、单位、范围、颜色映射）。
- **依赖线**：任务之间的 `dependsOn` 用有向箭头连接，形成任务流。
- **聚类/层级**：可按照关联的知识节点、项目阶段、能力包进行分组着色。

### 3.4 与知识节点的关联

- 新建任务时，用户可以从现有节点中选择关联节点，或新建节点。
- 任务完成后，可以一键把执行结果（笔记、数据、失败记录）回写为知识节点/证据。

### 3.5 Agent 调度（项目教练 + 学术研究员）

- 项目教练 Agent 根据目标生成里程碑与任务草案。
- 学术研究员 Agent 为每个任务自动搜索背景文献与学习资源，生成 `learningTools`。
- 用户可以在甘特图中拖拽调整时间、重要性、依赖，Agent 据此重新计算关键路径与风险。

### 改动文件

- `lib/types.ts`
- `hooks/useGraphStore.ts`（task CRUD）
- 新增 `components/ExecutionGantt3D.tsx`
- 新增 `components/TaskFlowEditor.tsx`
- 新增 `lib/execution-planning.ts`

- 修改 `components/BottomConsole.tsx`（Tab 名与渲染）

- [ ] 底部“时序/执行”Tab 打开后是多维执行工作台。

## 6. Agent 架构 → “逻辑推理”三层工作台

### 6.1 底部 Tab 重命名

- 原“Agent 架构”Tab 改名为 **“逻辑推理”**。
- 该 Tab 不再只是运行 Agent，而是管理**推理线程**。

### 6.2 推理的三层模型

基于 Judea Pearl 的因果阶梯与用户的反馈，v1.5 把推理明确分为三层：

#### L1：关联观察 + 表征记忆（当前图谱层）

- 统计共现、厘清关系、以视觉形式呈现。
- 对应现有“AI 生成节点导入图谱”。
- 产物：知识图谱、证据库、节点关系。

#### L2：干预推理（新增核心）

- 主动控制变量、做假设检验、因果与概率分析。
- 操作对象：条件、依赖、do-算子、控制变量、实验设计。
- 产物：
  - 干预假设卡片（“如果改变 X，Y 会如何？”）
  - 最小实验计划
  - 条件概率 / 因果图片段
- UI：在“逻辑推理”Tab 中打开某个推理线程，切换到“干预层”，对 claim 添加干预条件、设计对照、指定控制变量。

#### L3：反事实推理（新增高阶）

- 以一定强度推翻现有结论、排查隐藏漏洞、构建边界条件。
- 操作对象：反事实假设、否定案例、极限条件、鲁棒性测试。
- 产物：
  - 反事实场景（“如果当时没有 X，结论还成立吗？”）
  - 边界条件清单
  - 漏洞报告与修正建议
- UI：在“逻辑推理”Tab 中切换到“反事实层”，对已通过 L2 的 claim 提出反例、边界条件、替代解释。

### 6.3 推理线程与项目/任务的联动

- 推理线程不再只是独立画布，而是可以：
  - 从时序/执行任务中启动（“验证这个任务的关键假设”）。
  - 把 L2/L3 的验证结果回写为任务状态或新任务。
  - 把 L1 的图谱导入结果链接到推理线程作为证据。
- 项目教练 Agent 和学术研究员 Agent 的能力被拆分到：
  - **时序/执行 Tab**：生成任务草案、搜索学习资源。
  - **逻辑推理 Tab**：生成假设、寻找反例、评估因果强度。

### 6.4 底部推理窗口

- 在底部“逻辑推理”Tab 内，可以打开多个推理线程窗口（类似便签或 tab）。
- 每个线程窗口显示 L1/L2/L3 三层切换。
- 当前 `ReasoningCanvas` 改为悬浮/底部窗口，支持多线程并列。

### 改动文件

- `components/BottomConsole.tsx`（Tab 名与渲染）
- 新增 `components/LogicReasoningTab.tsx`
- 重构 `components/ReasoningCanvas.tsx` 为可嵌入底部窗口的组件
- 新增 `lib/causal-reasoning.ts`（干预/反事实辅助函数）
- 修改 `lib/reasoning.ts`（支持 L2/L3 prompt）
- 修改 `lib/types.ts`（`ReasoningThread` 增加 layer 字段）

### 验收

- [ ] 底部“逻辑推理”Tab 可创建/切换推理线程。
- [ ] 每个线程有 L1（关联）、L2（干预）、L3（反事实）三层。
- [ ] L2 支持添加干预条件、控制变量、生成最小实验。
- [ ] L3 支持提出反例、边界条件、替代解释。

## 8. 实施顺序建议

由于 v1.5 改动很大，建议按以下顺序分阶段推进：

| 阶段 | 任务 | 预计时间 |
|---|---|---|
| P0 | UI 打底：箭头高亮、节点详情定位、认知训练右移、输入 Tab 重组 | 1 天 |
| P1 | 时序/执行工作台：数据模型 + 3D 甘特图 + 任务流 | 3–4 天 |
| P2 | Agent 重构：项目教练/研究员输出任务草案与学习资源 | 1–2 天 |
| P3 | 逻辑推理三层：L2 干预 + L3 反事实 | 3–4 天 |
| P4 | 设计哲学更新、文档整理、build + 打包 | 1 天 |

**总计约 2 周**（单人 OPC）。

## 9. 风险与回退

| 风险 | 回退方案 |
|---|---|
| 3D 甘特图性能差 | 降级为 2D 时间轴 + 右侧指标面板 |
| 因果推理 prompt 不稳定 | L2/L3 降级为结构化表单，由用户填写，AI 只做辅助生成 |
| 底部 Tab 功能过多 | 把“输入”拆回左侧边栏，底部只保留执行/推理 |
| 右上面板过多遮挡 | 改为可折叠工具栏或左侧工具矩阵 |
