## 二、关键风险点专项说明

### 2.1 摄像头与人脸数据（高风险）

本项目视觉监督模块使用 MediaPipe FaceMesh 进行本地视线追踪与疲劳监测，属于处理敏感个人信息。

- **必须动作**：
  - 默认关闭摄像头功能，首次开启时弹窗单独同意。
  - 明确告知用户数据本地处理、不上传云端。
  - 不保存原始人脸图像，仅保存脱敏后的注意力评分/时间戳。
  - 提供随时关闭授权与删除本地数据的入口。

- **对应法规**：《个人信息保护法》《数据安全法》《App违法违规收集使用个人信息行为认定方法》。

### 2.2 AI 生成内容与算法备案（高风险）

项目调用 DeepSeek/Kimi 大模型 API，向用户输出摘要、节点、关系建议等内容。

- **必须动作**：
  - 完成互联网信息服务算法推荐备案。
  - 在 AI 生成内容旁添加显著标识（如“AI 生成”）。
  - 建立用户投诉与反馈渠道。
  - 大模型 API 调用日志留存不少于 6 个月。

- **对应法规**：《互联网信息服务算法推荐管理规定》《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》。

### 2.3 网络服务资质（中高风险）

若 Web 端通过域名向公众提供服务，必须完成 ICP 备案；若提供付费服务，需 ICP 经营许可证。

- **必须动作**：
  - 购买国内服务器或使用已备案云服务。
  - 官网底部悬挂 ICP 备案号。
  - 域名实名认证与备案主体一致。

### 2.4 桌面软件分发（中风险）

Windows 安装包若不进行代码签名，会被系统安全提示拦截，影响安装转化率。

- **必须动作**：
  - 购买 EV 或 OV 代码签名证书对安装包签名。
  - 安装流程中嵌入用户协议与隐私政策。
  - 提供卸载入口，并说明数据删除方式。

## 三、MVP 版本最低可上线清单

如果当前仅发布 **v1.x 本地桌面软件、免费分发、不涉及云端账号与数据同步**，建议至少完成以下事项：

| 序号 | 事项 | 优先级 |
|---|---|---|
| 1 | 公司注册、税务登记、银行开户 | 必需 |
| 2 | 软件著作权登记 | 必需 |
| 3 | 商标注册（核心类别） | 强烈建议 |
| 4 | 隐私政策 + 用户协议 | 必需 |
| 5 | 摄像头/人脸数据单独同意 + 默认关闭 | 必需 |
| 6 | AI 生成内容标识 | 必需 |
| 7 | 互联网信息服务算法推荐备案 | 必需（若提供 AI 推荐/生成服务） |
| 8 | 安装包代码签名证书 | 强烈建议 |
| 9 | 官网 ICP 备案（Web 端上线时） | 必需 |
| 10 | 第三方依赖许可证合规审查 | 强烈建议 |

## 四、v2.0 云端协作版本新增合规要求

当项目演进为 **NestJS + PostgreSQL + Redis + 账号系统 + 云同步 + 多人协作** 时，需在 v1.x 基础上额外完成：

| 序号 | 新增事项 | 说明 |
|---|---|---|
| 1 | 用户实名认证机制 | 手机号 + 短信验证码为最低要求；涉及内容发布需考虑身份证/人脸识别实名 |
| 2 | 等保三级（若用户规模达到要求） | 掌握大量用户个人信息或关键业务系统需三级等保 |
| 3 | 数据出境安全评估 | 若使用境外服务器、CDN 或第三方服务处理境内用户数据 |
| 4 | 个人信息保护影响评估（PIA） | 处理敏感个人信息前需完成评估 |
| 5 | 网络安全应急响应预案 | 建立 7×24 小时安全事件响应机制 |
| 6 | 内容审核与用户举报系统 | 多人协作场景下需防范违法违规内容传播 |
| 7 | 数据备份与灾备方案 | 云同步核心数据需多地域备份 |
| 8 | API 安全审计 | 防止越权访问、数据泄露 |

## 五、推进建议

1. **立即启动**：公司注册、商标注册、软件著作权登记。这三项周期长，是后续所有资质的基础。
2. **同步准备**：隐私政策、用户协议、敏感信息授权机制，建议与产品功能开发同步进行。
3. **上线前 2 个月**：启动算法备案、等保测评、ICP 备案、代码签名证书申请。
4. **上线前 1 个月**：完成安装包集成、应用商店审核、官网合规信息挂载。
5. **上线后**：建立年度合规审查机制，重点关注算法备案更新、等保复测、隐私政策更新。
