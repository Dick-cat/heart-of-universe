# 宇宙之心证据审查基石（v1.2 Meta-Methodology）

> 目标：为「超能模式」证据审查建立一套可解释、可扩展、可审计的元方法学。审查不是给节点打标签，而是逐项检查它作为"证据"在知识图谱中是否站得住脚。

---

## 1. 核心原则

1. **可证伪性优先**：一个论断的价值不在于它听起来多合理，而在于它能否被检验、能否被推翻。
2. **来源透明**：每个关键论断都必须能追溯到具体来源（论文、数据集、官方文档、一手记录）。
3. **方法可见**：不仅要知道"结论是什么"，还要知道"如何得出这个结论"。
4. **冲突必解**：当不同证据相互矛盾时，系统必须高亮冲突并提示用户做出判断，而不是自动消歧。
5. **置信度量化**：用结构化的维度评分替代简单的好/坏二元判断。

---

## 2. 证据审查五维度

### 2.1 来源可信度（Source Credibility）

| 等级 | 判定标准 | 示例 |
|---|---|---|
| A（高） | 同行评审期刊、顶会、官方数据集、权威教材、政府/国际组织官方文件 | Nature、Science、NeurIPS、WHO、CDC、NASA |
| B（中） | 预印本、技术博客、知名机构白皮书、经过验证的社区资源 | arXiv、Hugging Face、公司技术博客 |
| C（低） | 社交媒体、匿名论坛、未经验证的自媒体、营销内容 | Twitter/X、知乎回答、营销号文章 |
| X（未知） | 无法解析来源、本地文件无元数据、 dead link | 用户未命名笔记、失效链接 |

**审查点**：
- 来源域名是否在可信学术/技术列表中？
- 是否有 DOI / PMID / arXiv ID 等持久标识符？
- 是否为开放获取（Open Access）？
- 是否存在已知的撤稿、质疑或修正记录？
- 链接是否仍然可访问？

### 2.2 方法论严谨度（Methodological Rigor）

**审查点**：
- 研究设计是否明确？（实验、观察、仿真、理论推导、案例研究）
- 样本量/数据集是否足够？
- 是否有对照组 / 基线 / 消融实验？
- 指标定义是否清晰？评价指标是否与目标一致？
- 是否存在 p-hacking、多重比较、选择偏倚等统计风险？
- 方法是否可复现？是否有代码、数据、协议公开？
- 是否声明了局限性与假设边界？

### 2.3 论证一致性（Argument Consistency）

**审查点**：
- 节点内部是否存在自相矛盾？
- 结论是否超出证据所支持的边界？
- 是否存在滑坡谬误、稻草人、虚假两难等逻辑谬误？
- 从证据到结论的推理链是否完整？
- 与相邻节点（父节点、子节点、关系节点）是否一致？

### 2.4 证据完整度（Evidence Completeness）

**审查点**：
- 关键概念是否有定义？
- 是否有反例或竞争性解释被考虑？
- 是否标注了不确定性、置信区间、适用范围？
- 是否有时间、地点、条件等上下文？
- 附件是否覆盖核心证据（原始数据、论文、代码、记录）？

### 2.5 网络嵌入度（Network Embedding）

**审查点**：
- 该节点是否与其他节点建立关系？
- 关系类型是否明确？（支持、反驳、引用、扩展、对比）
- 是否存在孤立节点？
- 上游依赖（先修知识）是否完整？
- 下游影响（推论、应用）是否可追溯？

## 3. 问题分类与输出格式

当 AI 或算法发现问题时，必须输出结构化的"问题卡片"，而非简单否定。

```json
{
  "issues": [
    {
      "dimension": "source_credibility | methodology | consistency | completeness | network_embedding",
      "severity": "critical | major | minor | suggestion",
      "location": "节点标题 / 某条 contentItem / 某个 attachment",
      "description": "具体问题描述",
      "suggestion": "可执行的改进建议",
      "checkable": true,
      "how_to_verify": "用户可以尝试的验证步骤"
    }
  ],
  "verdict": "trusted | questionable | needs_review | insufficient_evidence",
  "score": 0.72
}
```

---

## 4. 元方法学检查清单

每个节点在通过"严格审查"前，应至少满足：

- [ ] 有至少一个可访问的来源或附件
- [ ] 关键概念有定义
- [ ] 结论与证据之间没有明显跳跃
- [ ] 标注了至少一条限制或边界条件
- [ ] 与至少一个其他节点建立了明确关系
- [ ] 不存在已知的撤稿/质疑/失效链接
- [ ] 若涉及量化结论，指标与统计方法清晰

## 6. 使用建议

1. **不要自动化通过**：AI 审查应输出问题清单，最终判断权留给用户。
2. **逐步完善**：初期允许节点存在"待审"状态，随着证据补充再提升可信度。
3. **领域模板**：医学、法律、工程等不同领域应使用各自的审查权重（医学更重来源与方法，工程更重可复现与验证）。
4. **记录审计**：每次审查结果应作为 contentItem 或 attachment 保留，形成审查历史。
