# 宇宙之心 v4.0 架构方案：个人认知系统 × 企业协同网络

> 版本：v4.0 架构提案（审阅版）
> 依据：docs/未来论述.md、docs/v3_0_PROPOSAL.md、docs/v2_0_PROPOSAL.md、docs/VERSION_ROADMAP.md
> 最后更新：2026-07-08

---

## 1. 定位变化：从工具到系统

v1.x–v2.x 的路线是「3D 知识图谱 + 认知训练 + 协作白板」。v3.0 升级为「项目驱动的能力包操作系统」。v4.0 的进一步跃迁是：

> **把个人认知系统作为最小单位，把企业协同网络作为可接入的上层结构。**

v4.0 不再把「个人学习」和「企业协作」做成两个功能模块，而是让个人先建立自己的认知系统，再让企业以「任务接口」的方式调用个人的能力包。个人不是企业的雇员，而是携带能力系统进入任务网络。

| 维度 | v3.0 | v4.0 |
|---|---|---|
| 核心单位 | 项目 / 能力包 | 个人认知系统 |
| 协作方式 | 多人共编一个项目 | 个人能力包被企业任务调用 |
| 数据主权 | 项目级 | 个人级，个人拥有完整数据 |
| 状态感知 | 视觉监督辅助 | 多模态个人状态中枢 |
| 价值输出 | 项目交付物 | 可验证的能力画像 + 任务记录 |
| 商业模式 | SaaS / 机构授权 | 个人免费 + 企业按任务/能力包付费 |

---

## 2. 核心假设

v4.0 基于 `docs/未来论述.md` 中的几个关键判断：

1. **劳动叙事正在破产**：学历和岗位无法继续为个人提供稳定上升路径。
2. **未来竞争单位是个人 + 能力系统**：谁能把学习内容转化为项目能力，并把项目能力沉淀为平台信用，谁就有议价权。
3. **控制演化**：个人必须通过制度与技术延展自己的认知—行动闭环。
4. **精控制需要基础设施**：从状态感知到反馈闭环，必须建设端侧传感、边缘推理、数据治理、反馈策略七层体系。
5. **个体携带能力系统进入任务网络**：企业购买的不是岗位，而是可验证的任务完成能力。

## 4. 第零层：本地基础设施层（数据主权优先）

v4.0 坚持**本地优先（local-first）**。个人的原始数据、原始视频流、原始行为序列、原始生理信号默认不上传。只有在个人主动选择共享某个能力包或任务记录时，才向企业层暴露脱敏后的结构化数据。

### 4.1 本地数据库

| 方案 | 适用阶段 | 说明 |
|---|---|---|
| **Dexie/IndexedDB** | 当前 v1.x | 浏览器原生，适合单机桌面端 |
| **SQLite + OPFS** | v4.0 推荐 | 桌面端使用 SQLite，Web 端使用 Origin Private File System |
| **Kuzu** | 可选增强 | 嵌入式图数据库，适合复杂图查询 |

推荐长期路线：**SQLite 作为主存储，Kuzu 作为图查询加速层**。所有数据默认本地文件，用户可随身携带。

### 4.2 本地 AI 推理

| 任务 | 推荐工具 | 理由 |
|---|---|---|
| 通用本地 LLM | **Ollama** | 7B–70B 模型一键管理，API 兼容 OpenAI |
| 端侧小模型 | **transformers.js / ONNX Runtime** | 隐私优先，浏览器/Node 均可运行 |
| 视觉模型 | **MediaPipe / YOLO / CLIP** | 已经在 v1.x 中使用，继续深化 |
| 嵌入模型 | **BGE / text-embedding-3-small** | 本地生成向量用于语义检索 |
| 推理编排 | **LangGraph.js** ⭐ | 状态机驱动的 Agent 工作流，支持循环和人在回路 |

### 4.3 同步协议

v4.0 的同步不是「把本地数据搬到云端」，而是「在多个个人设备之间同步同一个人的认知系统」。

| 方案 | 适用场景 |
|---|---|
| **Yjs** | 实时协作与 CRDT 同步 |
| **Electric SQL / PowerSync** | SQLite 的本地优先同步 |
| **自定义 Sync Engine** | 个人设备间的端到端加密同步 |

推荐：**个人设备同步用 Electric SQL；与企业共享用 Yjs + 权限控制**。

### 4.4 开放接口

为让更多生态接入，v4.0 必须提供标准化接口：

- **OpenAPI 3.0**：能力包导入/导出、任务状态查询、专注报告导出
- **MCP (Model Context Protocol)**：让外部 AI 助手能读取个人知识库
- **Plugin API**：视觉算法插件、交互算法插件、企业连接器插件
- **Webhook**：任务状态变化、专注报告生成、能力包被调用时通知

## 5. 第一层：状态感知与反馈层（精控制基础设施）

`未来论述.md` 强调，精控制不是从算法开始，而是从闭环基础设施开始。v4.0 把状态感知作为第一层，为后续认知行动闭环提供输入。

### 5.1 视觉监督

| 能力 | 当前状态 | v4.0 目标 |
|---|---|---|
| 人脸检测 | MediaPipe FaceMesh ✅ | 继续保留，本地运行 |
| 视线落点 | WebGazer.js（可选） | 估计屏幕注视区域 |
| 疲劳检测 | 眨眼频率 + 头部姿态 ✅ | 增加 HRV/呼吸协变量 |
| 情绪识别 | 未接入 | 仅作辅助，不进入主控制变量 |
| 姿态检测 | 未接入 | 坐姿、颈椎角度提醒 |

### 5.2 行为采集

- 鼠标轨迹、点击、滚动、停留时长
- 键盘输入节奏（非记录内容，仅记录节奏特征）
- 窗口焦点、Tab 可见性
- 节点操作序列（创建、编辑、连接、删除）
- 自写摘要、追问、修改次数

所有行为数据本地存储，不上传。

### 5.3 环境感知

- 屏幕亮度
- 环境光照（摄像头可估算）
- 环境噪音（麦克风可选）
- 座位姿态（IMU 可选）
- 当前任务内容

### 5.4 生理信号（可选扩展）

- 心率 / HRV（智能手表、耳机）
- 皮肤电反应（EDA，可选设备）
- 脑电（EEG，消费级设备，仅用于训练场景）

> **合规前提**：所有生理信号采集默认关闭，开启前需明确告知用途，支持随时撤回。

### 5.5 反馈通道

感知之后必须有反馈，才能形成闭环：

- 屏幕提示（温和，不打断）
- 声音提示
- 震动反馈（设备支持时）
- 任务难度调整
- 休息提醒
- 灯光调节（可选智能家居联动）
- 呼吸节律引导

## 6. 第二层：认知行动闭环层

把 `未来论述.md` 中的「输入—解析—知识—判断—行动—反馈—进化」压缩为四层：目标、判断、行动、复盘。

### 6.1 目标系统

- 长期目标、阶段目标、收入目标、学习目标、健康目标
- 目标拆解为能力包和任务
- 目标与个人知识图谱节点绑定

### 6.2 判断系统

- 假设管理
- 证据矩阵（支持 / 反对 / 待验证）
- 置信度追踪
- 反证与红队推演
- AI 审查员（来源可信度、方法严谨性、一致性、完整度、网络嵌入度）

### 6.3 行动系统

- 任务管理（依赖、优先级、状态）
- 2D 执行图
- 学习冲刺
- 最小实验
- 时间块规划

### 6.4 复盘系统

- 失败模式库
- 最佳实践库
- 能力成长曲线
- 周/月/项目复盘报告
- 自动将复盘结果回写知识图谱

## 7. 第三层：个人能力网络层

### 7.1 知识图谱（3D/2D 双视图）

- 继承 v1.x–v3.x 的 3D 力导向图能力
- 2D 执行图用于任务依赖可视化
- 节点类型：概念、原理、论文、证据、项目、任务、能力包
- AI 生成等级：Ⅰ / Ⅱ / Ⅲ
- 关系类型：依赖、支持、反驳、相关、派生

### 7.2 能力包（Capability Package）

v3.0 提出能力包四件套，v4.0 保留并扩展：

| 能力包 | 内容 | 企业调用方式 |
|---|---|---|
| 知识包 | 原理、概念边界、推导链、失败模式 | 作为任务输入 |
| 数据包 | 样本、文献、规范、日志、证据 | 作为参考依据 |
| 设备包 | 软件环境、脚本、配置、监控面板 | 作为执行环境 |
| 组织包 | 流程、角色、RACI、风险台账 | 作为协作模板 |
| 状态包 | 个人专注报告、能力画像、任务记录 | 作为可信度背书 |

能力包是个人与企业之间的接口单位。个人可以决定哪些能力包对企业可见。

### 7.3 证据矩阵

- 每份证据标注来源、可信度、支持/反对/待验证
- 与逻辑树节点双向绑定
- 自动识别证据冲突
- 可视化证据强度

### 7.4 任务执行图

- 2D 可视化任务依赖
- 节点大小反映工作量
- 颜色反映优先级（重要 + 紧急）
- 支持自动连线与手动调整

## 8. 第四层：企业任务网络层

v4.0 的企业协同不是「多人共编一个白板」，而是「企业发布任务，个人用能力包接单」。

### 8.1 企业任务池

企业可以发布：

- 短期任务（几小时到几天）
- 项目任务（数周到数月）
- 实习/学徒任务
- 研究/实验任务

每个任务标注：

- 所需能力包
- 预期交付物
- 验收标准
- 报酬/积分
- 数据主权要求

### 8.2 能力市场

个人可以把能力包上架到市场：

- 能力包描述
- 作品证据
- 任务完成记录
- 企业评价
- 价格或合作方式

### 8.3 项目接口

企业提供：

- 项目上下文（脱敏）
- 协作工具链接
- 审查门
- 验收流程

个人提供：

- 能力包匹配
- 执行计划
- 进度同步
- 交付物

### 8.4 合规审计

- 任务记录不可篡改
- 企业只能访问个人授权的数据
- 审计日志记录谁、何时、访问了什么
- 支持 GDPR / CCPA / PIPL 合规导出

## 9. 教育生态层：学校的新角色与学制重构

> 本章节回应一个关键质疑：如果个人认知系统可以直接对接企业任务网络，学校是否会被绕过？以及这对基础研究和科研生态会造成什么破坏？

### 9.1 问题的两面性

v4.0 不能只站在"企业效率"或"个人变现"的角度设计。必须同时承认两个事实：

**事实一：现有教育体系确实存在泡沫**

- 专业设置滞后于产业需求 3–5 年
- 教学方法陈旧，记忆导向而非能力导向
- 学历通胀：学历的筛选功能大于培养功能
- 论文导向的科研评价体系扭曲了科研本身

**事实二：完全绕过学校会对科研生态造成结构性破坏**

| 破坏维度 | 具体表现 |
|---------|---------|
| **基础研究萎缩** | 企业任务偏向短期应用，基础研究（数学、物理、基础理论）周期长、风险高，企业不会大规模投入 |
| **公共知识枯竭** | 大学产出的论文、开源代码、公共数据集是社会公共品；企业交付物归企业所有，不会自动转化为公共知识 |
| **高风险探索消失** | 学术研究允许失败、允许十年磨一剑；企业任务有明确验收标准，会把探索挤压到已知路径 |
| **学科交叉断裂** | 大学的多学科共置孕育意外发现；纯任务导向的协作是"按任务组队、任务结束解散" |
| **科学精神断层** | 大学培养批判性思维、方法论自觉、学术伦理；任务网络只看交付结果，不训练"为什么做、该不该做"的判断力 |

**结论**：学校不应该被绕过，而应该被**重构**。v4.0 的企业任务网络需要一个互补的**学术探索网络**。

### 9.2 三层教育体系

v4.0 框架下的新学制，不是单一的"四年本科 + 三年硕士"，而是三层弹性体系：

```
┌─────────────────────────────────────────────────────┐
│  第三层：前沿探索层（博士 / 博士后，4–6 年弹性）    │
│  目标：承担企业不愿做的高风险、长周期基础研究        │
│  产出：公共知识（论文、开源、数据集、方法论）        │
├─────────────────────────────────────────────────────┤
│  第二层：能力构建层（本科后2年 / 硕士，3–4 年弹性）  │
│  目标：通过真实项目构建能力包                        │
│  产出：可验证的能力包 + 项目交付记录                 │
├─────────────────────────────────────────────────────┤
│  第一层：基础认知层（K12 + 本科前2年，约 14 年）     │
│  目标：建立认知基础设施，不是灌输知识                │
│  产出：可自我更新的认知底层操作系统                  │
└─────────────────────────────────────────────────────┘
```

#### 第一层：基础认知层

核心转变：从"知识灌输"转向"认知基础设施建设"。

| 模块 | 内容 | 与个人认知系统的关系 |
|------|------|---------------------|
| 形式逻辑与批判性思维 | 如何论证、识别谬误、评估证据 | 训练判断系统 |
| 科学方法论 | 提出问题→假设→实验→验证→复现的完整循环 | 训练证据矩阵与复盘系统 |
| 基础读写算 | 语言、数学、编程基础 | 认知工具层 |
| 个人认知系统入门 | 注意力管理、知识图谱构建、学习方法元认知 | 直接使用本软件 |
| 至少一门深度学科体验 | 不是浅尝辄止，而是真正深入一个领域感受"知识深度" | 建立知识图谱的骨架 |

> 这一层的目的不是培养专家，而是让每个人拥有"可以自我更新的认知底层操作系统"。

#### 第二层：能力构建层

核心转变：从"专业学分制"转向"能力包项目制"。

- 不再按传统专业（计算机、金融、生物）划分，而是按**能力域**组织
- 学生用个人认知系统管理全部学习过程
- 学校提供四类资源：
  1. **项目库**：来自企业、研究机构、公共部门的真实项目
  2. **导师池**：教授、行业专家、资深从业者
  3. **设备资源**：实验室、算力、数据、软件工具
  4. **评估体系**：能力包完成度 + 项目交付质量 + 同行评议
- 毕业标准从"修满学分"变为"完成 X 个能力包 + Y 个真实项目交付"
- 学生**可以同时对接企业任务网络**，边学边做，用收入覆盖学费

#### 第三层：前沿探索层

核心转变：从"论文数量导向"转向"公共知识贡献导向"。

- 学校提供**探索基金**和**安全网**：博士生有充分试错空间，不因短期不出成果被淘汰
- 引入**"探索失败奖励"**：严谨的失败探索（排除了一条错误路径）同样有价值
- 研究成果必须以**公共知识形式**产出（论文、开源代码、公共数据集、方法论）
- 与企业任务网络的接口：应用导向的成果可以转化为企业任务，但基础研究保持独立

### 9.3 学校的五个新角色

学校从"知识传授者 + 学历发放者"，转变为：

| 角色 | 说明 | v4.0 中的对应模块 |
|------|------|------------------|
| **认知基础设施提供者** | 个人认知系统的标准、工具、方法论 | 第零层 + 第二层 |
| **项目生态组织者** | 对接企业和研究机构，组织真实项目供学生历练 | 第四层（扩展） |
| **基础研究的安全区** | 用公共资金保护企业不愿投入的高风险、长周期研究 | 学术探索网络层 |
| **能力评估的公证方** | 制定能力评估标准，颁发可信的能力画像认证 | 第三层（能力画像） |
| **学术伦理的守护者** | 培养批判性思维、学术诚信、社会责任感 | 判断系统 + 复盘系统 |

### 9.4 v4.0 架构修正：从"企业任务网络"到"机构任务网络"

原 v4.0 架构的第四层只有"企业任务网络"，这是不完整的。修正后：

**四类任务池**：

| 任务池 | 资助方 | 产出归属 | 周期 | 风险偏好 |
|--------|--------|---------|------|---------|
| 企业任务 | 企业 | 企业 | 短期（天-月） | 低风险、明确交付 |
| 学术任务 | 科研基金 / 学校 | 公共知识 | 中期（月-年） | 中高风险、探索性 |
| 公共任务 | 政府 /  NGO | 公共品 | 中期（月-年） | 社会价值导向 |
| 开源任务 | 社区 / 基金会 | 开源 | 长期（年） | 社区驱动、自组织 |

**新增"能力公证"模块**：学校（或第三方机构）作为中立公证方，对个人能力画像进行认证，增加企业和机构对能力包的信任度。

### 9.5 个人认知系统在教育中的引入路径

不建议"大面积突然引入"，应分四阶段推进：

| 阶段 | 时间 | 范围 | 内容 | 风险 |
|------|------|------|------|------|
| **工具层引入** | 0–1 年 | 大学选修课、研究生工具课 | 个人知识管理、学术研究方法课程中作为工具使用 | 低 |
| **课程层试点** | 1–2 年 | 部分专业的项目制课程 | 学生用系统管理学习过程，评估转向能力包 + 交付质量 | 中 |
| **学制层重构** | 3–5 年 | 新型能力本位学位项目 | 取消固定学制，以能力包完成度为毕业标准，学历 + 能力画像双证 | 较高 |
| **生态层融合** | 5–10 年 | 整个教育系统 | 个人认知系统成为教育基础设施，学-研-产连续光谱 | 最高 |

**不同教育阶段的差异化策略**：

| 阶段 | 引入程度 | 重点 |
|------|---------|------|
| K12 基础教育 | 低 | 注意力训练、学习方法、简单知识图谱 |
| 本科 | 中 | 工具使用、项目式学习、初步能力包构建 |
| 研究生 | 高 | 深度使用、研究项目管理、能力市场对接 |
| 职业教育 | 最高 | 完全项目驱动、能力包导向、直接对接企业任务 |
| 终身学习 | 最高 | 个人认知系统成为核心基础设施 |

## 11. 最适合这个项目的本地方案

综合考虑：
- 个人学习管理 + 规划
- 本地优先、隐私优先
- 后续要接入更多视觉、交互算法
- v2.0 之后要走向企业协同
- 当前是 TypeScript/Next.js/Electron 技术栈

**核心推荐：以 LangGraph.js 为编排引擎，以 Yjs + SQLite 为本地优先数据协作底座，以 Ollama 为本地模型基础设施。**

### 为什么选 LangGraph.js？

1. **状态机驱动**：把「生成 → 审查 → 修正 → 关系推断 → 布局」变成可观测、可重试、可人工介入的图。
2. **TypeScript 原生**：与现有技术栈无缝集成。
3. **支持循环**：Agent 可以反复迭代直到满足审查门槛。
4. **本地可运行**：结合 Ollama 可以完全离线运行。
5. **人在回路**：复杂审查节点可强制人工确认。
6. **未来可扩展**：同一套状态图可用于个人学习、企业任务分配、合规审计。

### 为什么选 Yjs + SQLite？

1. **本地优先**：数据先写本地 SQLite，再选择是否同步。
2. **CRDT 协作**：未来多人协作或与企业共享时，Yjs 解决冲突。
3. **个人数据主权**：原始数据不上传，只有授权的能力包才共享。

### 为什么选 Ollama？

1. **本地模型管理**：一键运行 Llama、Qwen、DeepSeek 等开源模型。
2. **API 兼容**：与现有 `/api/chat` 调用方式兼容。
3. **隐私**：敏感审查任务可完全本地执行。

## 13. 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 隐私与数据主权 | 原始行为、视频、生理数据高度敏感 | 本地优先，默认不上传，授权最小化 |
| 神经/生理数据合规 | 欧盟 AI Act、美国州法对神经数据严格限制 | 仅用于自愿训练场景，医疗边界声明 |
| 企业数据隔离 | 企业任务可能涉及商业机密 | 沙箱执行，审计日志，权限最小化 |
| 算法偏见 | 能力画像可能影响个人就业机会 | 可解释报告，支持申诉与修正 |
| 过度结构化 | 增加用户认知负担 | 从简单模式开始，逐步启用高级功能 |
| 开源生态治理 | Plugin API 可能引入恶意插件 | 签名验证、沙箱运行、社区审核 |
| **基础研究萎缩** | 企业任务偏向短期应用，可能导致人才逃离基础研究 | 学术任务池 + 探索基金 + 公共知识产出激励 |
| **教育公平性** | 个人认知系统可能放大"会学习者学得更快"的马太效应 | 基础教育免费接入、学校提供标准工具包、降低使用门槛 |
| **能力公证滥用** | 学校/机构的能力认证可能退化为新的"学历通胀" | 多源评估（企业评价 + 项目交付 + 同行评议）、动态更新、可申诉 |
| **学术伦理弱化** | 任务导向可能削弱对"为什么做、该不该做"的反思 | 判断系统内置伦理审查、学术伦理模块、批判性思维训练 |

## 14. 结论

v4.0 不是功能累加，而是**产品哲学升级**：

> 从「帮助个人管理知识」升级为「帮助个人构建可携带的认知系统，并以个人为节点连接企业、学术、公共部门等多元机构网络」。

核心技术选择：
- **LangGraph.js**：AI 编排与认知行动闭环
- **Yjs + SQLite**：本地优先、可协作的数据底座
- **Ollama**：本地模型基础设施
- **MediaPipe / WebGazer / YOLO**：视觉与状态感知
- **OpenAPI + MCP + Plugin API**：开放生态

**社会层面的核心判断**：

个人认知系统的出现，不是为了"绕过学校"或"颠覆教育"，而是为了**重构教育的价值锚点**——

- 学校不再是"学历发放机"，而是认知基础设施提供者、项目生态组织者、基础研究的安全区
- 企业不再是"岗位提供者"，而是任务发布者、能力调用者、实践场景提供者
- 个人不再是"被岗位定义的雇员"，而是携带能力系统进入任务网络的自主行动者

这套架构让个人在 AI 与机器人时代拥有自己的能力系统，同时保留进入企业、学术、公共部门等多元机构网络的开放接口。**它的终极目标不是取代学校，而是让教育回归其本质：帮助每个人构建可以终身更新的认知能力。**
