# 宇宙之心设计哲学：从“知道什么”到“因果推理 + 原创行动”

> 知识图谱记录的是“知道什么”（know-what）。
> 真正的理解是“知道为什么”与“能够推断”（know-why / reasoning）。
> 完整的工程落地是“推理 + 行动”（reasoning + action）。
> **原创能力则来自“反事实推理”的循环。**

---

## 1. 核心判断：知识图谱只是记忆，不是理解，更不是原创

一张图谱可以很大、很漂亮、节点之间的关系也可以很复杂，但它本质上仍然是**陈述性记忆**的外化：

- 它告诉你“有什么”。
- 它不告诉你“为什么是”。
- 更不告诉你“如果改变了某个条件，会发生什么”。
- 最不会告诉你“在什么边界条件下，这个结论会被推翻”。

AI 一次性生成一张图谱，只是把信息组织成了一种可视化形式。它不等于用户已经理解了这些概念，也不等于这些概念之间真的存在可靠的因果联系。

**“西蒙式”的节点堆砌是幻觉**：600 个节点、1000 条关系，可能只说明你把资料整理得井井有条，但不说明你具备了预测、干预或原创的能力。

**结论**：如果产品只停留在“生成图谱”这一层，它最终会变成一种高级笔记工具，而不是认知增强工具，更不是原创能力训练场。

---

## 2. 真正理解的三层结构：Pearl 因果阶梯

我们采用 Judea Pearl 的因果阶梯作为核心框架，把推理能力分为三层：

| 层级 | 名称 | 关键问题 | 认知动作 | 产品形态 |
|---|---|---|---|---|
| **L1** | **关联观察 + 表征记忆** | “X 和 Y 是否一起出现？” | 观察、分类、统计共现、厘清关系 | 知识图谱节点、证据库、关系网络 |
| **L2** | **干预推理** | “如果我改变 X，Y 会如何？” | 控制变量、假设检验、因果推断、实验设计 | 干预假设卡片、最小实验计划、条件-依赖图 |
| **L3** | **反事实推理** | “如果当时没有 X，结论还成立吗？” | 推翻结论、排查漏洞、构建边界条件、寻找替代解释 | 反事实场景、边界条件清单、漏洞报告 |

**只有 L1 → L2 → L3 的循环，才构成真正的理解、预测能力与原创能力。**

```text
        ┌─────────────────┐
        │   L3 反事实推理   │ ← 推翻、边界、原创
        └────────┬────────┘
                 │ 验证 / 修正
                 ▼
        ┌─────────────────┐
        │   L2 干预推理     │ ← 控制变量、假设检验
        └────────┬────────┘
                 │ 支持 / 反驳
                 ▼
        ┌─────────────────┐
        │ L1 关联观察+表征记忆 │ ← 共现、关系、可视化
        └─────────────────┘
```

### 为什么 L3 才是原创能力的核心？

- **L1 让你“看见”模式**。
- **L2 让你“操作”模式**。
- **L3 让你“想象不存在的世界”**：如果前提变了，结论会怎样？什么条件能让结论失效？是否存在被忽视的第三变量？

反事实推理是科学发现、工程创新、战略决策的共同起点。没有它，所有“学习”都只是模仿；有了它，才可能产生原创。

## 3. 四条产品原则

### 原则一：每个节点都必须回答“为什么”和“在什么条件下不成立”

一个孤立的节点价值很低。每个进入图谱的论断，都应该能回答：

- 它的证据是什么？
- 推理链是什么？
- 反例或竞争假设是什么？
- 适用范围与边界在哪里？
- 改变什么条件会让它失效？

> 产品实践：推理画布的 L1/L2/L3 三层要求用户不仅审查 claim，还要设计干预实验和反事实场景。

### 原则二：AI 输出必须经过人类审查的 staging 区

AI 不是真理机器。它的输出可能是：

- 来源不明或虚构的；
- 逻辑跳跃或过度泛化的；
- 带有训练数据偏见或立场倾向的。

因此，任何 AI 生成的内容都不应直接进入主图谱，而应先进一个**可审查、可拒绝、可修改的暂存区**。

> 产品实践：证据暂存区、推理步骤的“采纳 / 忽略 / 修改”、证据审查仪表、反事实漏洞报告。

### 原则三：每个项目都必须有“假设 → 干预 → 反事实 → 修正 → 沉淀”的闭环

理解不是一次性的，而是通过不断检验假设、主动干预、想象反事实、修正错误、沉淀经验来深化的。

```text
问题/目标
    │
    ▼
提出假设（claim）        ← L1 关联观察
    │
    ▼
设计干预实验            ← L2 干预推理
    │
    ▼
想象反事实 / 排查漏洞    ← L3 反事实推理
    │
    ▼
修正假设或扩展边界
    │
    ▼
设计最小行动 / 任务流
    │
    ▼
执行、记录、复盘
    │
    ▼
把验证后的知识沉淀为图谱节点与模板
```

> 产品实践：时序/执行工作台、逻辑推理 Tab、复盘模板库。

### 原则四：认知训练的目标不是“记住更多”，而是“推理更强”

注意力监督、摘要检查、手动节点等训练手段，最终目的不是让用户产生更多笔记，而是让用户：

- 习惯先自己推理再看 AI；
- 习惯为每个 claim 找证据；
- 习惯主动设计干预和反事实；
- 习惯在边界条件下审视结论。

> 产品实践：认知训练与推理画布联动，强制用户在采纳 AI 输出前完成 L2/L3 的简短检查。

## 4. 对 v1.x / v2 / v3 的启示

### v1.x：从“对话生成图谱”到“三层推理画布”

v1.x 的早期形态是：用户提问 → AI 直接返回 JSON 节点 → 直接进图。

这只停留在 L1。v1.5 之后的方向是：

- **L1**：用户提问 → AI 返回关联观察与候选 claim → 用户审查后进入图谱。
- **L2**：用户对 claim 添加干预条件、控制变量、设计最小实验。
- **L3**：用户提出反事实场景、边界条件、替代解释，排查隐藏漏洞。
- 只有经过 L2/L3 检验的 claim 才具备高置信度，并转化为任务与行动。

### v2：从“单机工具”到“因果推理 + 执行的协作平台”

v2 需要在本地能力之上增加：

- 多人协作的推理白板；
- 证据链与因果链的版本历史；
- 从已验证的 L2/L3 推理自动生成最小实验、任务、交付物；
- 认知训练与推理画布深度联动。

### v3：从“项目”到“能力包操作系统”

v3 的终极形态不是更好的图谱编辑器，而是：

- 任何目标都可以被拆分为“知识 / 数据 / 设备 / 组织”四包；
- 每包都通过“问题 → 原理 → 实验 → 工程 → 场景 → 监控 → 复盘”七步闭环推进；
- 每个闭环都经历 L1 → L2 → L3 的推理检验；
- 每个闭环的产出都沉淀为可复用的能力包模板与个人知识图谱。

## 5. 机器学习的边界：人必须留在闭环中，尤其是在 L2/L3

机器学习与 LLM 可以辅助：

- 快速检索与摘要；
- 提出候选假设；
- 检测表面上的不一致；
- 自动格式化与可视化；
- 枚举可能的干预条件或反事实场景。

但它们不能替代：

- **分布误差校验**：真实世界的误差往往来自训练数据之外的分布，需要人类判断模型是否适用。
- **多跳导航**：跨领域、跨时间、跨抽象层次的推理，仍然需要人类选择路径。
- **因果判断**：相关性不等于因果性，因果图的结构最终需要人类根据领域知识确认。
- **反事实想象**：AI 可以生成反事实候选，但“哪些反事实真正重要”取决于人类的目标与价值观。
- **行动责任**：工程落地涉及真实世界的后果，责任主体必须是人，而不是模型。

**因此，宇宙之心的 AI 定位是“可审查的推理助手”，而不是“自动得出结论的黑箱”。** 在 L1 它可以多做，在 L2/L3 它必须退后，让人类主导。
