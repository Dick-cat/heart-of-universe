## 2. Agent 集群：从“模拟”到“真 FARS”

### 2.1 当前 v1.0 实现（推荐用于个人学习）

- **机制**：一次 `response_format: json_object` 的 LLM 调用，由模型在单个 prompt 内扮演 5 位专家并输出结构化 JSON。
- **优点**：
  - 成本与单次普通 AI 对话相同（1 次 API 调用）。
  - 延迟低，用户体验接近普通聊天。
  - 不需要额外的基础设施（队列、状态机、缓存）。
- **缺点**：
  - 不是真正的多智能体辩论，模型可能“自说自话”。
  - 专家之间的观点冲突与迭代收敛较弱。
  - 复杂工程问题下输出深度受限。

### 2.2 真 FARS 式多 Agent 实现（v2.0 可选方向）

若后续需要真正的多智能体协作，可采用以下架构：

```text
用户输入
  → 需求分析师 Agent（独立 LLM 调用）
    → 架构师 Agent（基于需求输出）
      → 规划师 Agent（基于架构输出）
        → 评估者 Agent（批判与改进）
          → 研究员 Agent（补充理论与资源）
            → 共识合成 Agent（汇总并生成图谱 JSON）
```

#### 2.2.1 成本与性能影响

| 维度 | 当前单次调用 | 真 FARS 多调用 |
|---|---|---|
| API 调用次数 | 1 次 | 6–10 次（可并行部分） |
| Token 消耗 | 低（约 1.5k–3k 输出） | 高（可能 10k–30k 累计） |
| 延迟 | 2–6 秒 | 10–40 秒（串行）/ 5–15 秒（并行+合成） |
| 费用 | 与普通对话相同 | 5–10 倍于普通对话 |
| 稳定性 | 高 | 低（任一 Agent 失败需重试/降级） |
| 可解释性 | 中（仅最终 JSON） | 高（每步观点可追溯） |

#### 2.2.2 还需要注意的问题

1. **API 限流**：多 Agent 并行可能触发供应商 RPM/TPM 限制。
2. **错误降级**：某一位 Agent 超时或返回无效 JSON 时，需要回退到单 Agent 或提示用户重试。
3. **上下文长度**：前序 Agent 的输出可能很长，后续 Agent 的上下文窗口可能不足。
4. **状态持久化**：长流程需要临时存储每步结果，刷新页面后不能丢失。
5. **用户可控成本**：应允许用户选择“精简模式（1 次调用）”或“深度模式（多 Agent）”。
6. **可复用缓存**：相同输入的 Agent 结果可缓存，避免重复消费。
7. **模型选择**：复杂推理任务可能需要 `deepseek-reasoner` / `o1` 等推理模型，成本更高。
8. **后端架构**：当前 Edge Route 不适合长时间/多步骤任务，可能需要迁移到 Queue + Worker。

### 2.3 推荐路线

- **v1.x**：保持单次调用 Agent 集群，优化 prompt 与输出质量。
- **v2.0-beta**：可选的“深度 Agent 模式”，默认关闭，开启前明确提示成本与延迟。
- **v2.0+**：若用户规模扩大，引入后端任务队列与结果缓存。

## 3. 认知训练算法监督：目标人群与监督维度

认知训练监督不是“防挂机插件”，而是一套**帮助用户从被动接收 AI 输出转向主动思考**的辅助工具。其设计理念类似康复医学中的“运动再学习”：即使 AI 可以替用户完成，系统仍要求用户亲自完成关键认知动作，以维持和训练其思维能力。

### 3.1 目标人群

| 人群 | 训练重点 | 监督强度建议 |
|---|---|---|
| **ADHD / 注意力缺陷者** | 减少分心，强制完成阅读与总结闭环 | 中-高（定时提醒、分段阅读、即时反馈） |
| **学生 / 自学者** | 培养主动学习、批判性思维，避免抄答案 | 中（摘要+手动节点+自测） |
| **知识工作者** | 防止“AI 幻觉”导致的盲目信任 | 低-中（关键节点强制复核） |
| **老年用户** | 保持大脑活跃，防止数字依赖 | 中（语音朗读、简化流程） |

### 3.2 监督维度与指标

以下维度可按用户画像组合启用：

#### 3.2.1 基础行为指标

- **新建节点次数**：用户是否主动把理解转化为节点。
- **节点编辑时长**：在节点详情页停留与修改的时间。
- **内容输入速度**：打字速度、停顿模式（可检测复制粘贴 vs 手写）。
- **挂机/空闲时间**：AI 输出后多久用户才开始交互。
- **滚动与阅读时间**：是否真正浏览了 AI 输出，还是直接点“应用”。

#### 3.2.2 认知深度指标

- **阅读时间**：用户在 AI 输出上停留的时间，在内容阅读上的时间。
- **应用时间**：用户点击应用按钮后，等待 AI 处理的时间。
- **自写摘要质量**：长度、关键词覆盖、与原文的语义相似度/差异度。
- **追问深度**：用户是否提出澄清问题、反例或扩展问题。
- **节点连接数**：用户是否主动建立关系，而非孤立接受节点。
- **修改/迭代次数**：用户对 AI 生成内容的编辑、删除、重写比例，重要概念的修改次数。


#### 3.2.3 生理与情绪指标（未来扩展，需硬件/权限）
目前无法考虑以下指标：
- 眼动追踪阅读路径
- 心率/皮肤电反应（判断认知负荷）
- 面部表情（疲劳、困惑）
- 语音输入的流利度与停顿

### 3.3 算法干预方式

根据上述指标，系统可动态调整：

- **强制等待**：AI 输出后必须阅读 N 秒才能应用。
- **强制摘要**：应用前必须提交自写摘要。
- **强制手动节点**：用户需至少手动创建一个节点。
- **自适应难度**：若用户持续快速通过，提高要求；若用户明显困难，降低门槛。
- **提示与引导**：当检测到挂机或复制粘贴时，弹出引导问题。
- **认知负荷调节**：长文本自动分段，避免信息过载。
- **阅读时间限制**：用户必须在 N 秒内完成阅读，否则提示用户继续。

### 3.4 伦理、隐私与合规风险

1. **知情同意**：行为采集必须告知用户。
2. **数据最小化**：仅采集与训练目标直接相关的指标，不过度记录。
3. **避免歧视**：不同智力/身体状况用户的算法不应导致标签化或限制访问。
4. **医疗边界**：本工具不考虑医疗诊断或康复训练，仅作为认知训练辅助工具。
5. **儿童保护**：若面向未成年人，需符合 GDPR/COPPA 等法规。

### 3.5 多用户与个性化扩展

未来若面向大量用户，需要：

- **用户画像系统**：年龄、教育背景、认知状态、偏好目标。
- **可配置策略包**：不同人群启用不同监督组合。
- **A/B 测试框架**：验证不同算法对训练效果的影响。
- **模型个性化**：基于个人历史数据微调本地小模型（如 Llama 3 8B）作为监督策略。
- **机构管理后台**：学校可查看聚合统计（脱敏后）。

## 4. 版本建议

### 4.1 v1.0（当前）

- 修改日志 ✅
- 成本可控的单次调用 Agent 集群 ✅
- 认知训练开关与统计面板（占位）✅

### 4.2 v1.1 建议（低风险优化）

- 为 Agent 集群增加“专家观点可单独收藏为节点”。
- 修改日志支持导出 CSV/Markdown。
- 认知训练模式真正拦截 AI 输出：强制阅读 + 强制摘要 + 手动节点。

### 4.3 v2.0 候选方案

| 方案 | 内容 | 成本 | 风险 | 建议优先级 |
|---|---|---|---|---|
| A | 真多 Agent FARS 深度模式（可选开启） | 高 | 高 | 中 |
| B | 认知训练 MVP：强制摘要 + 手动节点 + 阅读计时 | 低 | 中 | 高 |
| C | 用户画像 + 可配置监督策略包 | 中 | 中 | 高 |
| D | 后端任务队列 + Agent 结果缓存 | 中 | 中 | 中 |
| E | 本地小模型辅助监督策略 | 中 | 中 | 低（长期） |

### 4.4 推荐 v2.0 MVP

优先实现 **B + C**：

1. 在认知训练模式下，AI 输出后进入“思考闭环”：
   - 必须阅读至少 30 秒（可配置）。
   - 必须提交自写摘要。
   - 必须手动创建至少一个节点。
   - 完成后才能应用 AI 的完整输出。
2. 允许用户选择训练强度模板：
   - 轻度：仅计时。
   - 中度：计时 + 摘要。
   - 重度：计时 + 摘要 + 手动节点 + 追问。
3. 统计面板展示训练进度与趋势。

## 5. 需要用户决策的问题

1. **Agent 集群**：v2.0 是否要做真多 Agent？还是继续优化单次调用的“伪 FARS”？
  如果开发2个版本，一个是plus版本，一个是免费版本。真多Agent版本需要支付额外费用，不过目前考虑免费版本上也可以使用。
2. **认知训练**：首要目标人群是谁？（ 学生学习 / 知识工作者 / 全人群）
   优先考虑学生学习，知识工作者，最后才是全人群。目前只能是兴趣版
3. **数据采集**：行为指标是否允许本地存储？是否允许上传匿名统计用于算法优化？
   目前只考虑本地存储
4. **商业模式**：未来是个人付费、机构授权，还是开源 + 服务？这影响后端架构选择。
   目前考虑开源+服务模式
5. **合规要求**：是否需要医疗软件认证、GDPR/CCPA 合规？
   目前不考虑医疗，这种认知康复只是类比。未成年人则是和市面上的未成年人模式一样。
